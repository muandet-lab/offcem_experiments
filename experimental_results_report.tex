\section{Experimental Setup}

\subsection{Research Question}

We study how the action clustering used by OffCEM affects off-policy evaluation performance in large discrete action spaces. In particular, we ask whether clustering quality, cluster count, and cluster balance influence bias,
variance, local correctness, and the ability of OffCEM to outperform standard OPE baselines.
The benchmark is a synthetic contextual bandit environment. We use a synthetic setting because the true target-policy value can be computed directly, allowing OPE estimates to be evaluated against ground truth. Each logged observation is a tuple $(x_i,a_i,r_i)$, where $x_i$ is a context, $a_i$ is the logged action, and $r_i$ is the observed reward. The goal is to estimate the target-policy value
$$V(\pi)=\mathbb{E}_{p(x)\pi(a\mid x)}[q(x,a)], \qquad q(x,a)=\mathbb{E}[r\mid x,a]$$

\subsection{Synthetic Reward Model}
The expected reward is constructed to follow a conjunct-effect structure with respect to the reward-generating partition:

$$q(x,a)=g(x,c_a)+h_{c_a}(x,a), \qquad c_a=\phi_{\mathrm{gen}}(a)$$

\paragraph{Clustering details.} Here, \(\phi_{\mathrm{gen}}\) is the action partition produced inside the synthetic data generator before rewards are constructed. It first builds 40-dim one-hot action features and then applies a chosen clustering method (e.g., the paper's original softmax-sampling procedure, K-means, random assignment, or feature bucketing) to obtain a label \(c_a\) for every action. These labels are then used to construct the reward function: for each cluster $c$, the generator assigns all actions with  $\phi_{\mathrm{gen}}(a)=c$ the same cluster-level component $g(x,c_a)$, and it draws the residual component $h_c(x,a)$ using parameters keyed by $c$. 

% Thus $\phi_{\mathrm{gen}}$ is the reward-generating partition, not merely an estimation-side grouping.

The term $g(x,c_a)$ represents the cluster-level effect, while $h_{c_a}(x,a)$ represents residual variation under that same partition. For a fixed context, $g(x,c)$ is shared by all actions in generating cluster $c$. It combines polynomial context-cluster interactions with nonlinear indicator terms, creating broad cluster-level preferences that vary with the context. The residual component $h_c(x,a)$ is generated separately for each cluster, with parameters keyed by the cluster index. 

\begin{equation*}
\begin{aligned}
g(x,c_a) ={}& g_{\mathrm{poly}}(x, e_{c_a}) + u_1 \mathbf{1}\left\{\frac{1}{\mathrm{mean}(x_{0:3})} < 1.5\right\} + u_2 \mathbf{1}\left\{ \frac{1}{\mathrm{mean}(x_{2:8})} < -0.5 \right\} + \\
& u_3 \mathbf{1}\left\{\mathrm{mean}(x_{1:3}) > 3.0 \right\} + u_4 \mathbf{1}\left\{\mathrm{mean}(x_{5:}) < 1.0 \right\}.
\end{aligned}
\end{equation*}

$$ h_c(x,a) = x^\top M_c \,\mathrm{onehot}(a) + \theta_{x,c}^\top x + \theta_{a,c}^\top \mathrm{onehot}(a)$$

In the continuous-reward experiments, the observed reward is sampled as
$$r=q(x,a)+\varepsilon, \qquad \varepsilon\sim\mathcal{N}(0,3^2)$$

This construction separates two sources of reward variation: variation explained by the reward-generating cluster and residual variation within that cluster. The separation is not intrinsic to the action features; it is defined by
\(\phi_{\mathrm{gen}}\). Therefore, when matched-mode experiments change the generating clustering, they also change the reward decomposition being evaluated.

\subsection{Logging and Target Policies}
The logging policy is a softmax policy over expected rewards:
$$ \pi_0(a\mid x) = \frac{\exp(\beta q(x,a))} {\sum_{a'}\exp(\beta q(x,a'))}, \qquad \beta=-0.1$$

Since $\beta$ is negative, the logging policy is intentionally suboptimal and assigns relatively more probability to lower-reward actions. The target policy is an $\epsilon$-greedy policy:
$$ \pi(a\mid x) = (1-\epsilon)\mathbf{1}\{a=a^*(x)\} + \frac{\epsilon}{|\mathcal{A}|}, \qquad \epsilon=0.2$$
where $a^*(x)$ is the action with the highest expected reward under context $x$. This creates a controlled distribution shift between the logging and target policies, making the OPE problem nontrivial.

\subsection{OffCEM Estimator}

OffCEM replaces action-level importance weights with cluster-level importance weights. For a clustering function $\phi$, the cluster-level importance ratio is 
$$w(x,c) = \frac{\pi(c\mid x)}{\pi_0(c\mid x)} = \frac{\sum_{a:\phi(a)=c}\pi(a\mid x)}{\sum_{a:\phi(a)=c}\pi_0(a\mid x)}$$
The estimator is
$$\hat V_{\mathrm{OffCEM}} = \frac{1}{n} \sum_{i=1}^n \left[w(x_i,\phi(a_i))(r_i-\hat f(x_i,a_i)) + \hat f(x_i,\pi)
\right], \text{ where } \hat f(x,\pi)=\sum_a \pi(a\mid x)\hat f(x,a)$$

The motivation for this estimator is that cluster-level weighting can reduce variance compared to action-level IPS-style weighting. However, this variance reduction comes at the cost of an additional structural assumption: \textbf{the reward model must be locally correct within each cluster}.

\subsection{Two-Stage Reward Regression}

The two-stage OffCEM reward model decomposes the reward estimate into a cluster-level term and a within-cluster residual term:
$$ \hat f(x,a)=\hat g_\psi(x,\phi(a))+\hat h_\theta(x,a)$$
The first stage learns within-cluster reward differences. It is trained on pairs of actions from the same cluster:
$$ \min_\theta \sum_{(x,a,b)} \ell_h \left(r_a-r_b, \hat h_\theta(x,a)-\hat h_\theta(x,b)\right)$$
This stage directly targets relative reward prediction inside each cluster. The second stage freezes $\hat h_\theta$ and learns the cluster-level offset:
$$ \min_\psi \sum_{(x,a,r)} \ell_g \left(r-\hat h_\theta(x,a), \hat g_\psi(x,\phi(a)) \right)$$

% Because the cluster-level offset is shared by all actions in the same cluster, it cancels when comparing two actions from that cluster. Therefore, the second stage cannot repair incorrect within-cluster contrasts learned by the first stage. This makes clustering quality directly relevant to the local-correctness behavior of OffCEM.

\subsection{Local Correctness Diagnostic}

OffCEM is unbiased under common cluster support and local correctness. Local correctness requires that the reward model preserve true within-cluster reward differences:
$$ q(x,a)-q(x,b) = \hat f(x,a)-\hat f(x,b) \quad \forall a,b \text{ with } \phi(a)=\phi(b)$$

To measure violations of this condition, we use a demeaned within-cluster error. Let $ e(x,a)=\hat f(x,a)-q(x,a)$
be the reward-model error. For each cluster $c$, define the cluster-mean error as
$$ \bar e_\phi(x,c) = \frac{1}{|A_c|} \sum_{a'\in A_c} e(x,a')$$
The demeaned error is
$$  e_{\mathrm{dm}}(x,a) = e(x,a)-\bar e_\phi(x,\phi(a))$$

We then report
$$ \dm(\hat f;\phi) = \mathbb{E}_x \left[\frac{1}{|\mathcal{A}|}\sum_a e_{\mathrm{dm}}(x,a)^2 \right]$$
This metric ignores cluster-level offset errors and isolates whether the reward model preserves relative differences among actions inside the same cluster. Low demeaned error indicates better local correctness.

\paragraph{Caveat.}
This is an oracle diagnostic: it uses the true synthetic expected reward $q(x,a)$, so it is not directly available in real logged data. It also measures local-correctness violation rather than OPE error itself; the join experiments are needed to test whether this diagnostic predicts OffCEM bias or relMSE.

\subsection{Clustering Variants}

We evaluate multiple hard action partitions  (i.e. actions are assigned to exactly 1 cluster $\phi(a) \in \{1,\ldots,K\}$)to test whether OffCEM is robust to different clustering choices. Here, we do not consider soft cluster assignments as they must either be hardened, for example by taking the largest membership, to be usable by OffCEM:

\begin{itemize}
  \item \texttt{original}: the paper/code method, implemented as a random linear score over action features, softmax with temperature, and stochastic sampling. The default temperature is $10$. This keeps it weakly feature-dependent. A breakdown of the setup is given below: 
  % but not geometrically coherent. 

  For every action ($a$) and cluster slot ($k$), it computes a logit score: $$s_{ak} = \tilde z_a^\top M \tilde e_k +\theta^\top \tilde e_k,$$ where $(z_a)$ and $(e_k)$ are the action feature vectors and the one-hot vector for cluster slot $k$ respectively. $(\tilde z_a)$ and $(\tilde e_k)$ are degree-1 polynomial features ( i.e. the original vector plus an intercept) and $(M)$ and $(\theta)$ are randomly sampled coefficient matrices/vectors from the fixed random seed. 
  
  In other words, each cluster slot ($k$) gets its own random linear scoring rule over the action features. Then the code standardizes all scores to mean 0 and variance 1, applies temperature-softmax,
   $$p(k \mid a) = \frac{\exp(s_{ak}/T)}{\sum_j \exp(s_{aj}/T)},$$
   
   and samples one cluster label for each action.
  
  \item \texttt{spectral}: This constructs a nearest-neighbor graph from the action-feature matrix, embeds via the graph Laplacian, and labels the spectral embedding with K-means. 

   \item \texttt{kmeans}: K-means clusters the observed one-hot action-feature matrix directly. It is run with $K$ clusters, $l_2$ distance, random initialization controlled by the experiment seed. The resulting hard labels define the estimation partition. 

  \item \texttt{agglomerative}: Ward linkage uses a Euclidean variance-minimization criterion. No kernel is supplied. 

  \item \texttt{random}: Independent random cluster labels sampled with random seed. Cluster sizes
  are therefore multinomial and may be imbalanced before any optional balance post-processing.

  \item \texttt{shuffled\_partition}: random equal-size partition. The method permutes action indices with \texttt{check\_random\_state(seed).permutation}, then slices the permutation into $K$ contiguous groups. Each group has size $\lfloor n_{\mathrm{actions}}/K\rfloor$ or one extra action for the first remainder groups. This is the size-balanced random control.

  \item \texttt{feature\_bucket}: Deterministic feature-only clustering by mean-centering the action-feature matrix, computing an SVD, projecting actions onto the \textbf{first right singular vector}, ranking projected values with ordinal ranks, and splitting the ranking into $K$ equal-frequency bins via  $\lfloor \mathrm{rank}(a)K/n_{\mathrm{actions}}\rfloor$. This is a fully deterministic assignment.  The other setups introduce stochasticity into the partition, making it hard to tell whether OffCEM fails because feature-based clustering is inherently inadequate or because the synthetic reward was generated from a feature-arbitrary partition. The \texttt{feature\_bucket} method was designed as a contrast to the \texttt{original} and random setups: when used as the data-generating partition, it provides a deterministic, feature-defined grouping that makes reward-feature alignment explicit. The SVD-and-bucketing construction is used to reduce the high-dimensional one-hot action features to a single reproducible feature axis and then form balanced clusters along that axis. This keeps the partition feature-based while avoiding extra randomness, unstable
  cluster sizes, or dependence on a particular iterative clustering algorithm.

  % \item \texttt{corrupt\_p}: A controlled corruption of the matched partition by selecting $\mathrm{round}(p\,n_{\mathrm{actions}})$ actions without replacement and reassigning each selected action to an independent uniform label in $\{0,\ldots,K-1\}$. A selected action can receive its original label, so the expected changed fraction is $p(1-\frac{1}{K})$. The output is dense-relabelled after corruption.
\end{itemize}

Across clustering variants, we also vary the number of clusters and optionally post-process assignments to control cluster balance. This allows us to separate the effects of cluster quality, cluster granularity, and cluster-size imbalance.

\subsection{Baselines and Metrics}

We compare OffCEM against standard OPE estimators: \IPS{}, \DM{}, \DR{}, and \MIPS{}. For OffCEM, we evaluate both one-stage and two-stage algorithmic-model variants.

Estimator accuracy is measured using relative MSE and the normalized bias and variance components:
$$ \relMSE = \frac{\mathrm{Bias}^2+\mathrm{Var}}{V(\pi)^2}, \qquad relBias = \frac{\mathrm{Bias}^2}{V(\pi)^2}, \qquad \relVar= \frac{\mathrm{Var}}{V(\pi)^2}$$
For local-correctness analysis, we report the demeaned error metric $\dm(\hat f;\phi)$ for the one-stage and two-stage reward models.

Together, these metrics allow us to distinguish three failure modes: high estimator variance, high estimator bias, and poor within-cluster reward structure. This is important because OffCEM may reduce variance through coarser cluster-level weighting while still becoming biased if the induced clusters violate local correctness. It is related to geometric coherence only when the observed feature geometry is reward-relevant (i.e. actions that look similar in the feature space also have similar reward structure), since feature-coherent clusters can still be reward-misaligned if the reward-generating partition follows a different or stochastic structure.


\section{Completed Experiments With Results}

\subsection{Clustering Experiment: Matched and Mismatched Modes}

\paragraph{Purpose.}
This experiment studied how clustering method, cluster count, and cluster balance affect OffCEM OPE performance.

\paragraph{Matched and mismatched setups.} The key distinction is whether the estimation partition used by OffCEM is the  same partition that generated the synthetic reward. In matched mode,  $\phi_{\mathrm{est}}=\phi_{\mathrm{gen}}$: the data generator first constructs  the action clusters, uses those exact labels to define $q(x,a)$, and \texbf{then passes the same cluster labels to OffCEM for reward-model training and cluster-level importance weighting}. Thus matched mode is an oracle-aligned setting; it tests how OffCEM behaves when the chosen clustering is exactly the reward-relevant partition, not whether the method can rediscover that partition.

In mismatched mode, the reward is generated from one partition but OffCEM is estimated with another. In these experiments, data were generated with the  \texttt{original} partition, while the estimation partition was replaced by alternatives such as \texttt{kmeans}, \texttt{spectral}, \texttt{random}, or \texttt{shuffled\_partition}. The cluster count was kept fixed within each cell, so the mismatch is primarily in which actions are grouped together rather than in the requested number of clusters. This setup tests robustness to partition misalignment: an estimation cluster may combine actions whose rewards were generated under different cluster-level and residual components, which can break the local-correctness structure that OffCEM relies on.


\paragraph{Design.}
Matched mode used the same clustering method for reward generation and estimation. Completed matched results cover \texttt{original}, \texttt{kmeans}, \texttt{spectral}, and \texttt{random}; cluster counts 10, 50, and 200; natural
and balanced cluster balance; 15 seeds. Mismatched mode generated data with \texttt{original}/natural clustering and estimated with \texttt{original} plus alternative clusterings. It used cluster counts 10, 50, and 200 with 60 seeds. The checkpoints contain all five estimation clusterings at $n_c=200$, with some clusterings absent at lower cluster counts due to the run structure.



\paragraph{Findings.}
Cluster count was the dominant factor in matched mode as shown in both Fig. \ref{fig: matched1} and Fig. \ref{fig: matched2}: OffCEM 2-stage relMSE roughly doubled from $n_c=10$ to $n_c=200$. No learned method consistently beat the original clustering in the matched results; differences among matched methods were much smaller than the cluster-count effect. Random clustering degraded at higher cluster counts. Bias, not variance, dominated OffCEM error.

In mismatched mode in Fig. \ref{fig: mismatched}, non-original estimation clusterings performed much worse than the original estimation clustering. At $n_c=10$, OffCEM with \texttt{kmeans} had relMSE 1.692 versus 0.466 for \texttt{original}. At $n_c=200$, all non-original methods were clustered around relMSE 1.53--1.60, while \texttt{original} was 1.019.

\paragraph{Caveat.} These runs should be treated as exploratory rather than final. Currently there exist two direct bugs: non-reproducible original clustering and computing $V_{\mathrm{true}}$ at the wrong cluster count. There are also setup-level confounds: matched mode changes the reward-generating partition as well as the estimation partition, $V_{\mathrm{true}}$ is computed from a separate sampled synthetic world, pairwise reward-model training is not fully seeded, and sparse within-user/within-cluster pairs make cluster-count effects partly a data-availability effect. The completed checkpoints remain useful for qualitative orientation, but the relMSE magnitudes and method rankings should be regenerated before being treated as final.

\subsection{Local Correctness: Cluster-Count Sweep}

\paragraph{Purpose.}
This experiment directly tested whether the OffCEM two-stage reward model preserves within-cluster relative reward differences.

\paragraph{Design.}
The sweep used $n_c\in\{10,50,100,200\}$ and methods \texttt{matched}, \texttt{original}, \texttt{random}, and
\texttt{shuffled\_partition}. The default setup used 3000 logged rounds, 1000 actions, reward noise 3, target $\epsilon=0.2$, and 10 seeds.



\paragraph{Findings.}
The exact matched partition had the lowest local-correctness violation at every cluster count, as shown in Fig.~\ref{fig:lc_sensitivity}. Mismatched partitions retained a weaker two-stage improvement, but the large matched advantage disappeared. More clusters reduced within-cluster heterogeneity and lowered the oracle demeaned error, even though separate relMSE experiments showed that more clusters can worsen OPE bias/variance. Size imbalance mainly affected tail risk: larger clusters had higher per-cluster demeaned error, making random partitions worse in their worst clusters.

\begin{figure}
    \centering
    \includegraphics[width=1\linewidth]{fig_lc_sensitivity.png}
    \caption{Local-correctness sensitivity across cluster count, observed cluster size, and temperature. Finer partitions lower the oracle demeaned within-cluster error, while larger clusters create higher-error tails; temperature has little effect on recovering the reward-generating partition.}
    \label{fig:lc_sensitivity}
\end{figure}

\paragraph{Caveat.}
Increasing ($n_c$) changes the reward-generating partition itself and mechanically creates smaller clusters, which reduces within-cluster heterogeneity. Hence, the sweep is strongest as a qualitative matched-versus-mismatched check, not as a deployable or fully policy-weighted error diagnostic.

\subsection{Local Correctness: Temperature Sweep}

\paragraph{Purpose.}
This tested whether lowering the original clustering temperature makes the generating partition more feature-coherent and therefore recoverable by \texttt{kmeans}.


\paragraph{Design.}
Cluster count was fixed at 50. Methods were \texttt{matched}, \texttt{kmeans}, \texttt{original}, and \texttt{random}. Temperature was selected from the set \{1, 2, 5, 10 \}.



\paragraph{Findings.}
The temperature hypothesis was refuted. Results were nearly flat across temperature in Fig.~\ref{fig:lc_sensitivity}. \texttt{kmeans} was worse than \texttt{random} at every temperature. The adjusted Rand index between the generating partition and K-means remained near zero even at very low temperatures. Temperature changed cluster-size balance, not feature-geometric coherence.

\subsection{Feature-Coherent Local Correctness Benchmark}

\paragraph{Purpose.}
This benchmark tested whether the fragility observed on the default feature-arbitrary reward is intrinsic to OffCEM or an artifact of the synthetic reward being keyed to a non-geometric partition.



\paragraph{Design.}
The primary run generated rewards using the deterministic \texttt{feature\_bucket} partition and estimated with \texttt{matched}, \texttt{feature\_bucket}, \texttt{kmeans}, and \texttt{random}. A contrast run generated rewards using \texttt{kmeans}. Both used $n_c=50$ and 10 seeds.


\paragraph{Findings.}
When the reward genuinely follows an observable feature geometry (Fig. \ref{fig:feature_coherent_dm}), \texttt{feature\_bucket} recovers oracle-level aggregate local correctness without access to the generating labels. K-means still fails because it captures a different  feature geometry from the one that generated the reward. The refined conclusion is that local correctness depends on alignment between the estimation partition and the reward residual geometry; that alignment can be achieved without oracle labels, but feature use alone is insufficient.

\begin{figure}
    \centering
    \includegraphics[width=0.7\linewidth]{fig_feature_coherent_dm.png}
    \caption{Feature-coherent benchmark. The deterministic feature-bucket partition matches the oracle local-correctness level when reward is generated from the same observable geometry, while K-means fails because it induces a different geometry.}
    \label{fig:feature_coherent_dm}
\end{figure}

\paragraph{Caveat.}
The positive result is an existence proof, not a universal feature-clustering guarantee. In the fully deterministic \texttt{feature_bucket} setting, using the same rule for reward generation and estimation is effectively reward-clustering without explicit oracle labels: the partition is recoverable because the reward generator was defined from that exact observable rule. Thus, the result shows that OffCEM works when the estimation partition matches the reward residual geometry, but it does not show that arbitrary feature clustering will discover that geometry. A different feature method, such as K-means, can still fail.



\subsection{Join Experiment on Feature-Coherent Rewards}

\paragraph{Purpose.}
This experiment paired local-correctness violation and OffCEM estimator error on identical runs. In this case, the reward generated by the deterministic \texttt{feature\_bucket} partition. It tested whether oracle-free feature-aligned clustering reaches oracle estimator error at full grid scale.


\paragraph{Design.}
The grid contained:
$ n_c\in\{10,50,200\},\quad \epsilon\in\{0,0.2,0.7\},\quad \sigma\in\{1,3\},\quad n\in\{1000,3000\}$
For each of the 36 cells, the experiment evaluated six clustering conditions: \texttt{matched}, \texttt{kmeans}, \texttt{random}, \texttt{shuffled\_partition}, \texttt{corrupt\_p0.25}, and \texttt{corrupt\_p0.75}, with 10 seeds.

\paragraph{Findings.}
Within-cell diagnostic performance remained strong: mean Spearman correlation of $\dm$ with $\relBias$ was +0.85, positive in 36/36 cells. The strict argmin match dropped because \texttt{matched} and \texttt{feature\_bucket} were genuine co-winners.

\subsection{Controlled FCM Overlap}

\paragraph{Purpose.}
This controlled experiment tested whether FCM membership uncertainty adds information beyond policy-weighted DM when true action overlap is known.


\paragraph{Design.}
The generator created known two-cluster memberships and varied the fraction of ambiguous actions. It used two reward modes: \texttt{reward\_relevant}, where rewards mix latent cluster reward functions using the known memberships, and \texttt{feature\_only}, where feature overlap is present but rewards use only the primary hard cluster. The completed run covered 2 reward modes, 4 ambiguity levels, 10 seeds, and 1760 partition evaluations.

\paragraph{Findings.}
FCM did not recover the known memberships: ambiguity AUC was approximately chance, estimated entropy was high even at zero true ambiguity, and membership entropy had near-zero or negative correlation with the reward-mixture effect.
FCM-hard OffCEM error was nearly identical between reward-relevant and feature-only modes, indicating that degradation came mainly from worsening FCM partitions as features overlapped, not from successful detection of
reward-relevant ambiguity. Adding FCM uncertainty improved held-ambiguity error calibration modestly but not ranking.

\subsection{Domain-Informed and Outcome-Aware Clustering}

\paragraph{Purpose.}
This experiment tested whether OffCEM clusters should come from generic metadata, external domain knowledge, auxiliary-data outcome profiles, or hybrid representations.

\paragraph{Design.}
The synthetic environment separated generic metadata, true domain classes, observed noisy domain attributes, and latent outcome classes. Domain alignment took values $\{0,0.5,1\}$ and domain-label noise took values $\{0,0.25,0.5\}$, with 10 seeds per cell. Methods included feature-only K-means, domain-informed K-means, oracle outcome-profile K-means, estimated outcome-profile K-means from an independent auxiliary log, a hybrid
representation, shuffled-domain, and random controls.

\paragraph{Findings.}
Observable domain knowledge helped only when it was reward-relevant, as shown in Fig.~\ref{fig:domain_alignment_noise}. With clean domain labels, the domain-informed partition improved from relMSE (1.384) at zero domain alignment to (0.454) at half alignment and (0.003) at full alignment. This benefit degraded quickly under domain-label noise. Oracle outcome-profile clustering was the strongest overall reference, selecting the lowest-error partition in (84/90) cells. Policy-weighted DM selected the same argmin in (84/90) cells and achieved a mean within-cell Spearman correlation of (0.77) with OffCEM squared error.

The estimated-outcome arm was inconclusive: it did not recover outcome structure because the auxiliary reward model used generic action features that were independent of domain and outcome labels. Thus, the experiment validates clean domain knowledge and oracle outcome geometry, but not the current estimated outcome-profile implementation.

\section{Cross-Experiment Conclusions}
OffCEM works when the estimation partition aligns with the reward residual geometry. The default synthetic benchmark makes that alignment hard for ordinary feature clustering because the original reward partition is stochastic and nearly non-geometric. Local-correctness violation degrades smoothly under partition corruption, and the oracle demeaned metric ranks clustering choices well within a fixed problem, but it is not a portable threshold and is not directly observable in real data. The strongest positive results are the feature-bucket and clean domain-informed settings: oracle labels are unnecessary when the observable clustering geometry is actually reward-relevant. Current fuzzy, possibilistic, and rough membership-uncertainty routes do not improve OffCEM on the tested representations, while relaxed local-correctness bounds are valid but too wide for practical use.

  \item \textbf{Regenerate the old clustering relMSE runs.} Re-run matched and mismatched clustering experiments after fixing the original-clustering seed issue and the $V_{\mathrm{true}}$ cluster-count bug.   \item \textbf{Build a deployable local-correctness proxy.} Test whether held-out within-cluster residual $R^2$ or a policy-weighted logged-data proxy tracks the oracle demeaned metric without using true $q(x,a)$.
  \item \textbf{Repair the estimated-outcome representation.} Re-run the domain/outcome experiment with an auxiliary model that can represent action identity or posterior reward profiles, rather than only generic action features.
  \item \textbf{Sharpen relaxed-local-correctness bounds.} Replace exact synthetic epsilon with a logged-data-calibrated estimate and test whether the resulting intervals remain valid while becoming narrower.
\end{enumerate}

\section{Geometric coherence}
We use the term \textbf{geometric coherence} to mean that cluster membership is stable with respect to distances in the observed action-feature space: actions that are nearby in the one-hot feature representation tend to receive the same cluster label, while actions that are far apart tend to be separated. This is distinct from simply having the right number of clusters or balanced cluster sizes. Two partitions can both have $K$ clusters of similar sizes and still disagree almost completely if they group different regions of the feature space.

This distinction matters because the reward-generating partition need not be geometrically coherent. In the \texttt{original} generator, cluster labels are sampled from a flattened softmax over random linear scores. As a result, the assignment is only weakly feature-dependent: nearby actions can be split across different clusters, and distant actions can be assigned together. Thus an estimation clustering such as K-means may be geometrically coherent in the observed feature space while still being poorly aligned with the reward-generating partition.
